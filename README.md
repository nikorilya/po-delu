# «По делу» — тренажёр обратной связи

Telegram Mini App для руководителей: за 15–18 минут человек учится давать обратную связь, после которой люди меняются, а не обижаются. Четыре уровня: распознать → исправить → собрать → применить в разговоре.

На старте человек выбирает путь: **с уроками** (перед каждым уровнем микроурок на минуту) или **сразу к практике** (для тех, кто знает SBI). Урок можно открыть в любой момент: кнопкой «Освежить теорию» перед уровнем или «?» внутри уровня.

Проект статический: HTML, CSS и JavaScript-модули без сборки и без бэкенда. Работает внутри Telegram и в обычном браузере.

> **Статус контента: черновик.** Все тексты в `content.json` помечены как черновик (`_meta.status: "draft"`) и требуют проверки автором.

## Быстрый старт

```bash
# из папки проекта
python3 -m http.server 8080
# открыть http://localhost:8080
```

Открывать `index.html` двойным кликом нельзя: браузер не даст загрузить `content.json` по `file://`. Нужен любой локальный сервер (`npx serve`, `python -m http.server`, Live Server в VS Code).

Полезные параметры для показа в портфолио:

| Параметр | Что делает |
|---|---|
| `?theme=dark` / `?theme=light` | принудительная тема вне Telegram |

Сбросить прогресс в браузере: шестерёнка на карте уровней → «Сбросить прогресс».

## Публикация

### GitHub Pages
1. Залить содержимое папки в репозиторий (файлы в корне или в `/docs`).
2. Settings → Pages → Deploy from a branch → выбрать ветку и папку.
3. Через минуту приложение доступно по адресу `https://<user>.github.io/<repo>/`.

### Vercel
`vercel deploy` из папки проекта или импорт репозитория в веб-интерфейсе. Framework preset: **Other**, build command пустой, output directory — корень.

### Подключение к Telegram
1. В [@BotFather](https://t.me/BotFather) создать бота (`/newbot`).
2. `/newapp` → выбрать бота → указать URL с GitHub Pages / Vercel и короткое имя (например, `app`). Ссылка вида `https://t.me/<bot>/app` — это и есть ссылка на тренажёр.
3. По желанию: `/setmenubutton` — кнопка запуска в чате с ботом.
4. Вписать итоговую ссылку в `content.json` → `app.botLink`. Она уходит в сообщение «Поделиться результатом».

## content.json

Файл можно править без изменения кода. После правок проверьте, что JSON валиден (например, на jsonlint.com), и пройдите изменённый уровень.

### Верхний уровень

| Ключ | Что внутри |
|---|---|
| `_meta` | статус (`draft`), версия, дата — версия выводится внизу экрана «Об авторе» |
| `app` | название, подзаголовок, `botLink`, тексты приветствия (`{name}` → имя из Telegram) |
| `author` | имя, роль, строка о себе, ссылки `[{label, url}]` |
| `about` | экран «Об авторе и методике»: зачем, модель SBI+, устройство уровней, принципы |
| `errorTypes` | типология ошибок: `id → {title, group}`; `group` связывает ошибку с профилем |
| `characters` | персонажи: `key → {name, role, color}`; `color` — пастельный цвет аватара |
| `ui` | все подписи интерфейса (кнопки, вердикты, шаблоны вроде `{score} из {max} баллов`) |
| `levels` | 4 уровня, см. ниже |
| `profiles` | итоговые профили и правила их выбора |

### Общие поля уровня

```json
{
  "id": 1,
  "type": "swipe | fix | build | dialog",
  "title": "Факт или ярлык",
  "goal": "строка под названием на карте",
  "duration": "~2 мин",
  "intro": "одна-две строки о механике перед стартом",
  "unit": ["фраза", "фразы", "фраз"]
}
```

`unit` — формы слова для счётчика «8 фраз».

### Уровень 1 — `swipe`

```json
"timerSec": 6,
"pointsPerItem": 10,
"items": [{
  "id": "l1_1",
  "text": "Ты вечно всё делаешь в последний момент",
  "answer": "judgment",            // "fact" или "judgment"
  "errorType": "generalization",   // только для judgment
  "character": "dima",             // кому адресована фраза
  "explain": "1–2 строки разбора",
  "hears": "как это услышит сотрудник (с маленькой буквы)"
}]
```

### Уровень 2 — `fix`

```json
"items": [{
  "id": "l2_1",
  "character": "marina",
  "context": "одна строка: что случилось",
  "bad": "плохая фраза в пузыре",
  "positive": true,                 // необязательно: задание на позитивную обратную связь
  "options": [
    { "id": "a", "text": "…", "errorType": "vague", "why": "…", "hears": "…" },
    { "id": "c", "text": "…", "correct": true, "why": "…", "hears": "…" }
  ]
}]
```

Ровно один вариант с `"correct": true`. Варианты показываются в порядке из файла.

### Уровень 3 — `build`

```json
"slots": [{ "key": "situation", "label": "Ситуация", "hint": "когда и где" }, …],
"okWhy": "разбор, если всё собрано верно",
"orderHint": "разбор, если блоки верные, но перепутан порядок",
"partialNote": "{n} из 4 на месте",
"items": [{
  "id": "l3_1",
  "character": "dima",
  "title": "Релиз в пятницу",
  "context": "2–3 предложения ситуации",
  "blocks": [
    { "id": "s", "slot": "situation", "text": "…" },        // 4 верных блока — с полем slot
    { "id": "t1", "errorType": "label", "text": "…", "why": "…", "hears": "…" }  // 3 ловушки
  ],
  "hears": "реакция сотрудника на верно собранное сообщение"
}]
```

Блоки перемешиваются одинаково при каждом запуске (порядок зависит от `id` ситуации). Готовое сообщение склеивается из верных блоков в порядке слотов, поэтому первый блок может заканчиваться запятой, а следующий начинаться со строчной буквы.

### Уровень 4 — `dialog`

```json
"timerSec": 20,
"trustStart": 50,
"timeoutTrust": -10,
"timeoutWhy": "разбор при истечении времени",
"dialogs": [{
  "id": "oleg_late",
  "character": "oleg",
  "title": "…",
  "context": "служебное сообщение в начале чата",
  "opening": "первая реплика сотрудника",
  "start": "n1",
  "nodes": {
    "n1": {
      "onTimeout": { "reply": "реплика при молчании", "next": "n2" },
      "options": [
        { "id": "a", "good": true, "trust": 10, "text": "…", "why": "…", "hears": "…",
          "reply": "ответ сотрудника", "next": "n2" },
        { "id": "b", "trust": -15, "errorType": "label", … , "next": "n2" }
      ]
    },
    "n4": { … "next": null }        // null — конец разговора
  },
  "endings": [
    { "minTrust": 70, "type": "agreed", "title": "Договорились", "epilogue": "…" },
    { "minTrust": 40, "type": "failed", "title": "Разговор не получился", "epilogue": "…" },
    { "minTrust": 0,  "type": "left",   "title": "… ушёл обиженным", "epilogue": "…" }
  ]
}]
```

- `trust` — изменение доверия от −20 до +15; итог ограничен диапазоном 0–100.
- Ветки сходятся: плохие ответы на 3-м ходу ведут в узел-«ремонт» `n3b`, хорошие — сразу в `n4`. Поэтому разговор длится 4–5 ходов.
- Финал выбирается по наибольшему `minTrust`, который не превышает итоговое доверие.

### Уроки — `levels[*].lesson`

Урок перед уровнем: 2–3 карточки, около минуты. Поле необязательное: если у уровня нет `lesson`, урок и кнопки «Освежить» / «?» не показываются.

```json
"lesson": {
  "title": "Тест видеокамеры",
  "duration": "1 мин",
  "cards": [ … ]
}
```

Типы карточек:

| `type` | Поля | Что показывает |
|---|---|---|
| `idea` | `title`, `text`, `chipsLabel` + `chips[]` (слова-маркеры), `list[{term, text}]`, `note` | ключевая идея; все поля, кроме `title`, необязательны |
| `contrast` | `title`, `situation`, `bad{text, note}`, `good{text, note}` | одна ситуация, плохая и хорошая фраза |
| `traps` | `title`, `text`, `traps[{name, example, profile}]`, `note` | ловушки с ярлыком профиля (`profile` — ключ из `profiles.items`) |
| `steps` | `title`, `text`, `steps[{name, text}]`, `note` | нумерованная последовательность (модель, ходы в разговоре) |
| `parts` | `title`, `character`, `parts[{slot, text}]`, `note` | сообщение, разложенное по слотам уровня 3 (`slot` — ключ из `levels[2].slots`) |
| `check` | `question`, `quote`, `options[{text, correct, why}]` | мини-проверка, не в зачёт; ровно один `correct: true`; «Дальше» открывается после ответа |

Пишите примеры для уроков на ситуациях, которых нет в заданиях уровня: урок объясняет принцип, а не подсказывает ответы.

Тексты развилки — в `app.welcome` (`question`, `ctaLearn`, `ctaLearnHint`, `ctaPractice`), подписи урока — в `ui.lesson*`.

### Профили

```json
"profiles": {
  "masterThreshold": 0.15,
  "tieOrder": ["prosecutor", "commander", "diplomat"],
  "items": { "master": {…}, "diplomat": {…}, "prosecutor": {…}, "commander": {…} }
}
```

Каждый профиль: `name`, `emoji` (используется в заголовке и сообщении для шаринга), `tagline`, `tips` (2–3 совета).

## Как считаются баллы и профиль

**Баллы.** +10 за верный ответ в уровнях 1–2 и +10 за каждый верный слот в уровне 3 (до 40 за ситуацию). В уровне 4 баллы за разговор равны итоговому доверию (до 100).

**Звёзды.** ≥90% от максимума — 3, ≥70% — 2, иначе 1. На карте хранится лучший результат.

**Профиль.** Строится по последней попытке каждого уровня:

1. Доля ошибок = ошибочные ответы / все ответы (в уровне 3 каждый слот — отдельный ответ, в уровне 4 — каждый ход).
2. Если доля ошибок меньше `masterThreshold` (15%) → «Мастер фидбэка».
3. Иначе ошибки суммируются по группам (`errorTypes[*].group`), побеждает самая частая группа. При равенстве решает порядок `tieOrder`.

Какие ошибки попадают в группы:

| Ситуация | Тип для профиля |
|---|---|
| Уровень 1: оценку приняли за факт | тип ошибки карточки (например, `generalization`) |
| Уровень 1: факт приняли за оценку | не учитывается в группах, только в доле ошибок |
| Уровень 1/4: время вышло | не учитывается в группах, только в доле ошибок |
| Уровень 2/4: выбран неверный вариант | `errorType` варианта |
| Уровень 3: в слот поставлена ловушка | `errorType` ловушки |
| Уровень 3: верный блок не на своём месте | не учитывается в группах, только в доле ошибок |

## Сохранение прогресса

Состояние — один компактный JSON (≈1–2 КБ), который пишется после каждого ответа:

- в **Telegram CloudStorage** (Bot API 6.9+, с задержкой 400 мс и принудительно при сворачивании приложения);
- в **localStorage** — запасной вариант и кэш; вне Telegram только он.

При запуске берётся более свежая копия. Незаконченный уровень хранится в `run`. Открыв приложение заново, пользователь попадает на интро уровня с кнопкой «Продолжить» и продолжает с того же задания. Разговор в уровне 4 хранится как путь `[узел, вариант]` и полностью восстанавливается.

Для уроков хранятся выбранный путь (`path`: `learn` / `practice`), пройденные и пропущенные уроки (`lessonsSeen`) и открытый урок с номером карточки (`lesson`). Если приложение закрыли посреди урока, он откроется на той же карточке. Если человек сам вышел из урока на карту, урок не откроется при следующем запуске сам, но продолжится с той же карточки, когда человек снова зайдёт в уровень. «Пройти заново» сохраняет путь и показывает уроки снова.

## Telegram

- При старте: `ready()`, `expand()`, `disableVerticalSwipes()` (7.7+), цвет шапки и фона — `secondary_bg_color`.
- Тема: SDK сам выставляет CSS-переменные `--tg-theme-*`, стили используют их с запасными значениями. Тёмная и светлая тема переключаются автоматически, включая смену темы на лету.
- **MainButton** — главные действия: «Начать», «Продолжить», «Следующий уровень», «Мой результат». Внутри уровней кнопки (`Дальше`, `Проверить`) сделаны на странице, рядом с контентом.
- **MainButton на приветствии** — «Сначала коротко объясни» (путь с уроками). «Знаю, сразу к практике» — кнопка на странице над ней.
- **BackButton** — возврат на карту уровней (прогресс уже сохранён). Когда урок открыт поверх уровня через «?», «Назад» закрывает урок и возвращает к заданию.
- **SettingsButton** — настройки (уроки перед уровнями, таймеры, сброс прогресса).
- **HapticFeedback** — `success` / `error` на ответ, `light` на тапы по блокам в уровне 3.
- **Поделиться** — открывает выбор чата через `https://t.me/share/url` с текстом «Мой стиль обратной связи — … А какой у тебя?» и ссылкой из `app.botLink`. Вне Telegram — системное меню «Поделиться» или копирование в буфер.

Все вызовы проверяют версию клиента (`isVersionAtLeast`), поэтому на старых клиентах приложение не падает, а просто не использует недоступную функцию.

## Аналитика

`js/analytics.js` → `track(event, params)`. Сейчас события пишутся в консоль (`[track] …`).

| Событие | Параметры |
|---|---|
| `app_open` | `resumed_level` |
| `path_chosen` | `path` (`learn` / `practice`) — выбор на приветствии |
| `path_changed` | `path`, `prev` — переключение в настройках |
| `lesson_start` | `level`, `source` (`auto` — перед уровнем, `refresh` — «Освежить», `help` — «?» в уровне), `card` |
| `lesson_check` | `level`, `correct` — ответ на мини-проверку |
| `lesson_complete` | `level`, `source`, `time_ms`, `check_correct` |
| `lesson_skip` | `level`, `card` — на какой карточке нажали «Пропустить» |
| `level_start` | `level`, `resumed` |
| `answer` | `level`, `item_id`, `correct`, `error_type`, `time_ms` |
| `level_complete` | `level`, `score`, `stars` |
| `dialog_end` | `dialog_id`, `trust`, `ending` |
| `profile_shown` | `profile`, `error_rate` |
| `share_click` | `profile` |
| `restart` | `source` (если сброс из настроек) |

`error_type` в `answer`: тип ошибки, `timeout`, `missed_fact` (факт принят за оценку) или `order` (уровень 3: верные блоки не на своих местах). Ко всем событиям добавляются `path`, `session` и `ts`.

Благодаря `path` в каждом событии можно сравнить, как проходят уровни те, кто смотрел уроки, и те, кто сразу пошёл в практику. А `lesson_start` с `source: "help"` показывает, на каком уровне люди чаще всего застревают и ищут подсказку.

Подключить сервис — добавить приёмник в конце `analytics.js`:

```js
// Яндекс Метрика (счётчик подключается в index.html)
addSink((event, params) => window.ym && ym(COUNTER_ID, 'reachGoal', event, params));

// Свой эндпоинт
addSink((event, params) =>
  navigator.sendBeacon('https://example.com/collect', JSON.stringify({ event, ...params })));
```

## Доступность

- Таймеры можно отключить в настройках (отдельно для разминки и разговоров); таймеры встают на паузу, когда приложение свёрнуто или поверх уровня открыт урок.

## Решения, которые стоит проверить автору

- **Обращение в профилях.** В ТЗ описания профилей даны на «вы», а тон интерфейса — на «ты». В контенте всё на «ты» («Ты так бережёшь человека…»).
- **«Пустая похвала»** в ТЗ не отнесена ни к одному профилю. Здесь она в группе «Дипломат»: это тоже уход от конкретики.
- **Таймаут** засчитывается как ошибка, но не влияет на выбор профиля: он говорит о скорости, а не о стиле.
- **Повторное прохождение уровня** обновляет данные для профиля (последняя попытка), а звёзды на карте сохраняют лучший результат.
- **Если доля ошибок ≥15%, но все ошибки «без типа»** (таймауты, порядок блоков), профиль — последний в `tieOrder` (сейчас «Дипломат»).
- **Перетаскивание блоков** в уровне 3 не реализовано: по ТЗ основная механика — тапы, drag-and-drop был необязательным.
- **Реплики пользователя** в уровне 4 написаны без глаголов прошедшего времени, чтобы не зависеть от рода.
- **Персонажи и цифры** (клиенты «Вектор», «Альфа-Логистика», сроки, суммы) вымышленные.
- **Мини-проверка в уроке** не влияет на баллы и профиль: это переключение из режима «читаю» в режим «думаю», а не экзамен. Результат уходит только в аналитику.
- **Урок уровня 2 называет профили** («Дипломат», «Прокурор», «Командир») до финала. Так человек заранее знает язык, на котором с ним будет говорить итоговый экран.
- **Урок уровня 4 без проверки**: сам уровень — это практика сразу после урока.
- **Пользователи версии 0.1** уже прошли приветствие без развилки. Для них включён путь «сразу к практике», уроки можно включить в настройках.

## Проверка перед релизом

- [ ] Вычитать `content.json`, снять пометку `draft`, поднять `version`.
- [ ] Заполнить `author` и `app.botLink`.
- [ ] Пройти все уровни в Telegram на iOS и Android, в светлой и тёмной теме.
- [ ] Закрыть приложение посреди уровня 2 и уровня 4 — должно продолжиться с того же места.
- [ ] Проверить «Поделиться результатом» из Telegram.
- [ ] Пройти оба пути: «Сначала коротко объясни» и «Знаю, сразу к практике».
- [ ] Открыть «?» посреди уровня 1 и уровня 4: таймер должен стоять, «Назад» в Telegram возвращает к заданию.
- [ ] Засечь время полного прохождения (цель — 12–18 минут, с уроками ближе к 18).
